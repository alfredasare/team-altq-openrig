# Approvals: what runs, what asks, what never happens

Two layers:
1. **`hooks/guard.py`** runs before every Bash command in every seat. It blocks the never-allowed list and forces a
   prompt to Alfred for the gated list, **even in auto mode**. Check it with `hooks/guard.py --selftest` (90 cases).
2. **Each desk's `.claude/settings.json`** (generated by `bin/build-desks.sh` from `config/`):
   - lets read-only commands run without asking;
   - refuses to read secret files (`.env` files, key files, `~/.config/gcloud`, `~/.ssh`, the GitHub CLI's login);
   - refuses edits to Alfred's checkout `~/AltQ/40act` for every seat (the builders use worktrees).

| Tier | Examples | Behaviour |
|---|---|---|
| Read | `git` reads, `gh pr view/list/checks`, `gh run list/view`, `gh api` GETs, `gcloud storage ls/cat`, `gcloud run … list/describe`, `gcloud builds list/log`, `gcloud logging read`, `bin/db.sh dev/prod/test` (dev and prod refuse writes), `curl` reads (SEC), `docker ps/logs` | Runs |
| Dev work | edits in a worktree, `bun test`, `bun run lint/typecheck/build`, local commits, pushing a named feature branch, `gh pr create`, sync v2 on dev that replays, `bun --env-file=<file> run/test …` | Auto mode decides; prompts in supervised mode |
| Gated | `gh pr merge`, `gh pr review --approve`, pushing to `main`/`development`/`feature/new-sync`, `git reset --hard`, `bin/db.sh prod-write` or `dev-write`, a direct `mongosh`, tests or a migration against `40act_dev`, sync v2 with `--fresh` or `--reread` (model cost), `gcloud` deploys/job runs/builds/IAM/auth changes, writes to the bucket, `gcloud secrets … access`, Atlas and Auth0 CLIs, Stripe writes or `--live`, `bun -e` with an env file, touching `40act-redis`, `docker volume prune`, `rm -rf` outside temp or the team's worktrees, reading a credentials file | **Always asks Alfred** |
| Never | force push or `+refspec`, history rewrites, deleting from the bucket (`gcloud storage rm`, `gsutil rm`), printing a Google credential (`gcloud auth print-*-token`), `gh auth token`, `gh repo delete`, a live Stripe key on a command line, `docker compose … -v`, `pkill`/`killall` | **Blocked** |

## Modes
- **Auto mode for every seat** (Alfred, 3 Nov 2026: "can't be approving every 5 seconds"). Claude Code runs routine
  actions on its own judgment and asks only about risky ones, and the guard still forces a prompt for the gated
  tier. It was set with `rig seat set-permissions <seat> --mode auto` and applies from each seat's launch.
- **The gated and never tiers hold in every mode.**
- **Back to accept-edits** for a seat: `rig seat set-permissions <seat> --mode acceptEdits --reason "<why>"`.

## Changing a rule
- **The guard:** add a case to `CASES` in `hooks/guard.py` with the expected result, change the check, and run
  `--selftest`.
- **Settings:** edit `config/base-settings.json` or `config/roles/<seat>.json`, then `bin/build-desks.sh`.
  Seats pick changes up at their next launch.
